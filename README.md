## 🌟 Project Overview

<div align="center">
  <img src="https://readme-typing-svg.demolab.com?font=Fira+Code&size=18&duration=2500&pause=800&color=10B981&center=true&width=700&lines=Solving+real+problems+in+education+%26+sales...;Using+state-of-the-art+large+language+models...;At+absolutely+zero+monthly+cost." alt="Subtitle Typing Animation" />
</div>

<br/>

**EduMind AI** is a **production-grade, full-stack AI platform** designed to solve real-world problems in education and sales using state-of-the-art large language models. The platform delivers **five distinct AI-powered capabilities** through a single, unified interface, all backed by enterprise-grade governance controls.

### 🎯 The Five Challenges

<div align="center">

| # | Challenge | Module | Description | Status |
|:---:|:----------|:-------|:------------|:------:|
| **Ch1** | 🎓 AI Answer Evaluator | `evaluator` | Multi-layer scoring with concept analysis | ✅ **Active** |
| **Ch2** | 📝 Question Generator | `generator` | AI-driven exam question creation from past papers | ✅ **Active** |
| **Ch3** | 🔍 Spelling Detector | `spelling` | OCR-powered error detection with PDF annotation | ✅ **Active** |
| **Ch4** | 🎤 Voice AI Tutor | `voice_tutor` | Real-time Socratic voice tutor with interruption | ✅ **Active** |
| **Ch5** | 💼 Sales Assistant | `sales` | RAG-based product recommendations with lead scoring | ✅ **Active** |

</div>

### 🚀 Installation Steps

```bash
# ── Step 1: Clone Repository ─────────────────────────────
git clone https://github.com/dhruv-005/edumind-ai-platform.git
cd edumind-ai-platform

# ── Step 2: Backend Setup ────────────────────────────────
cd backend
```

## 🛡️ AI Governance Framework

```
╠═══════════════════════════════════════════════════════╣
║  Pillar 1: Content Safety        ✅ Always Active     ║
║  Pillar 2: Audit Trail           ✅ Every Request     ║
║  Pillar 3: Human Oversight       ✅ Auto-triggered    ║
║  Pillar 4: Bias Detection        ✅ Statistical Mon.  ║
║  Pillar 5: Rate Limiting         ✅ Per IP + User     ║
║  Pillar 6: Data Privacy          ✅ Auto-delete       ║

╚═══════════════════════════════════════════════════════╝
```

---

### 🔒 Pillar 1 — Content Safety

```
📨 Input arrives
    │
    ├── 🚫 Profanity filter
    ├── 💉 Prompt injection detection
    ├── 🔓 Jailbreak attempt detection
    ├── 🪪 PII detection (emails, phones, cards)
    └── 📚 Educational relevance check (Voice Tutor)

📤 Output generated
    │
    ├── ☢️  Harmful content scanner
    ├── ⚖️  Bias detection
    └── 👶 Age-appropriateness check
```

**Blocked patterns:** SQL injection · Script injection · Instruction overrides · PII in logs

---

### 📋 Pillar 2 — Audit Trail

Every AI decision is logged with:

<div align="center">

| Field | Description |
|:------|:------------|
| `request_id` | Unique UUID per API call |
| `timestamp` | UTC timestamp |
| `challenge` | Which AI module was used |
| `input_hash` | SHA-256 of input (not raw data) |
| `model_used` | Exact model version |
| `confidence_score` | `0.0` – `1.0` confidence |
| `governance_status` | `passed` / `flagged` / `blocked` |
| `processing_time_ms` | Latency measurement |
| `human_review_triggered` | Boolean flag |

</div>

> 🗓️ **Retention policy:** 90 days standard · Deletable on user request.

---

### 👁️ Pillar 3 — Human Oversight

Automatic human review triggers:

<div align="center">

| Condition | Trigger | Action |
|:----------|:--------|:-------|
| Evaluator confidence < 60% | Low confidence | Teacher review queue |
| Generated question similarity > 90% | Near duplicate | Approval required |
| OCR confidence < 70% | Poor scan quality | Human verification |
| Student distress keywords detected | Emotional signal | Counselor escalation |
| Sales lead score ≥ 85 | Hot lead | Immediate human notification |

</div>

### ⚖️ Pillar 4 — Bias Detection

Statistical monitoring for:
- **Gender bias** — Checks generated content for gender-stereotyped language
- **Cultural bias** — Ensures questions/examples are culturally inclusive
- **Evaluation fairness** — Monitors score distributions across student groups
- **Sales fairness** — Equal recommendation quality regardless of customer profile

## ⚠️ Known Limitations

### 🔧 Technical Limitations

<div align="center">

| Limitation | Impact | Workaround |
|:-----------|:-------|:-----------|
| SQLite database | Not suitable for >100 concurrent users | Switch to PostgreSQL |
| Single server | No horizontal scaling | Docker + load balancer |
| Whisper STT accuracy | 85–90% in noisy environments | Requires quiet environment |
| Local Tesseract OCR | Lower accuracy on complex layouts | Use Google Vision API |
| ChromaDB startup | Slow reload (~30s) on startup | Use Qdrant or Pinecone |
| Edge TTS rate limits | Occasional delays under heavy load | TTS queue with caching |

</div>

### 🤖 AI Model Limitations

<div align="center">

| Limitation | Description |
|:-----------|:------------|
| Hallucination risk | LLMs can generate plausible but incorrect feedback |
| Language support | Optimized for English; other languages have reduced accuracy |
| Subject depth | Very specialized topics may get imprecise evaluations |
| Context window | Very long answers (>3000 tokens) may be truncated |
| Knowledge cutoff | No awareness of events after training date |

</div>

### 🛡️ Governance Limitations

<div align="center">

| Limitation | Description |
|:-----------|:------------|
| Bias detection | Works best with >100 samples per group |
| Content filter | May have false positives for legitimate technical content |
| Human review queue | In-memory only; does not persist across restarts |
| Audit logs | SQLite-based; use dedicated log management for production |

</div>
